# ECE 309 Project 1 — LLM Mini-Harness (Vibe Coding)

A minimal terminal-based LLM agent harness written in C, built for ECE 309
Project 1. It fakes the "LLM" with a mock model function (no API calls, no
network), but implements the actual harness pieces you'd need around a real
model: a core loop, bounded conversation memory, and tool execution.

This project was built using vibe coding — I wrote the spec/architecture
myself and used Claude to generate the C implementation from it. The full
process (prompts, constraints, what I caught and sent back for fixes) is in
[`vibe_coding_log.md`](./vibe_coding_log.md).

## What it does

- **Core loop** — reads a line from the terminal, hands it to the mock model,
  prints the response, repeats until you type `exit`.
- **Context management** — keeps the last 5 turns of conversation in a
  fixed-size ring buffer. Each turn's memory is allocated on the heap and
  freed either when its slot gets recycled or when the program shuts down, so
  memory stays flat no matter how long the session runs. Type `history` at
  any point to see what's currently stored.
- **Tool execution** — the mock model can't do math (on purpose — that's the
  point of this requirement), so it delegates to a calculator tool. Try:
  `calc 6 * 7`, `calc 12 / 4`, `calc 9 - 100.5`.
- **Everything else** falls back to a canned "hello" greeting or a default
  echo response that also reports how many turns are currently in context.

## Build & run

```bash
gcc harness.c -o harness
./harness
```

Example session:

```
You: hello
Model: Hello! I'm a mock model with a 5-turn memory. Try 'calc 6 * 7'.
You: calc 6 * 7
Model: [tool:calculator] 6 * 7 = 42
You: history
  [1] user : hello
  [2] model: Hello! I'm a mock model with a 5-turn memory. Try 'calc 6 * 7'.
  [3] user : calc 6 * 7
  [4] model: [tool:calculator] 6 * 7 = 42
  [5] user : history
Model: (showing conversation history above)
You: exit
Shutting down. Goodbye!
```

Or with `make`:

```bash
make        # builds ./harness with -Wall -Wextra
make test   # rebuilds and runs test.sh (state + memory checks)
make clean  # removes build artifacts
```

## Testing

`test.sh` was generated by an AI assistant per requirement #5 of the spec (see
the log for the exact prompt). It:

1. Rebuilds `harness.c` with `-Wall -Wextra` and confirms a clean build.
2. Pipes a fixed, deterministic conversation into the compiled binary and
   checks the transcript for the exact response expected at each step
   (greeting, tool call, history readback, default echo, clean exit).
3. Checks for memory leaks — with `valgrind --leak-check=full` if it's
   installed, otherwise by rebuilding with `-fsanitize=address,undefined` and
   checking for ASan/LSan errors.

Run it with:

```bash
bash test.sh
```

It exits 0 only if every check passes.

## Requirements this satisfies

1. Core Loop
2. Context Management (5-turn history, safe alloc/free)
3. Tool Execution (calculator)
4. Vibe Coding Log (`vibe_coding_log.md`)
5. AI-Generated Testing (`test.sh`)
